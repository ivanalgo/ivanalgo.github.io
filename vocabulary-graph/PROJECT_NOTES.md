# Word Orbit：项目思想与实现说明

本文档供后续维护者和 AI 编程工具阅读。修改项目前，应先理解这里记录的产品目标、数据约束和已经验证过的设计取舍。

## 1. 产品目标

Word Orbit 是一个面向英语学习者的离线词汇关系图。用户输入一个单词后，以它为中心查看语义相近的词，并可点击任意近邻继续探索。

核心原则：

- 关系必须尽量表达语义，而不是只表达拼写相似。
- 页面是静态 HTML、CSS 和 JavaScript，不依赖远程数据库。
- 英文单词是第一视觉层级；中文释义和相似度是辅助信息。
- 点击节点切换中心词，点击扬声器只播放发音，不触发跳转。
- 首屏保持紧凑，尽量减少用户在看到搜索框和关系图之前的滚动。

## 2. 当前数据规模与文件

- 词汇量：50,000。
- 每个词保存 40 个语义近邻。
- `data/manifest.js`：记录基础词库和各字母分片的原始大小、词数与数据版本。
- `data/core.js`：50,000 个单词、中文释义和模型信息，约 1.9 MB。
- `data/neighbors-a.js`～`neighbors-z.js`：按中心词首字母拆分的 26 个近邻数据文件。
- `generate_data.py`：重新生成词库、中文释义和近邻数据。
- `app.js`：搜索、绘图、跳转、历史返回、发音和响应式节点数量。
- `loader.js`：先加载基础词库和当前单词分片，再启动页面；其余分片在浏览器空闲时后台逐个加载。
- `styles.css`：网站基础布局。
- `meanings.css`：中文释义、彩色节点、紧凑布局和发音按钮等后续样式。

不要在浏览器中加载完整 GloVe 模型。模型只用于离线生成。网页首次只加载基础词库和当前字母分片，不应恢复一次性加载全部近邻的旧方案。

## 3. 词库与中文释义

### 英语词表

词频数据来自 `hermitdave/FrequencyWords` 的完整英语词频表。生成器先取前 80,000 个合法候选词，再保留其中有 GloVe 向量的前 50,000 个。

筛选规则：

- 只保留小写英文字母组成的词。
- 长度为 3～15 个字符。
- 按词频顺序去重。
- 必须存在于选定的 GloVe 模型中。

扩大词库时不要只修改 `WORD_COUNT`，还要同步扩大候选池，并检查目标词是否被 GloVe 覆盖。

### 中文释义

中文释义来自 ECDICT。为了让节点保持紧凑，只保留第一行中前两个简短义项，并去除常见词性前缀。

ECDICT 对专名、人物或低频词可能给出过长、过时或不准确的释义。生成后应抽查常用词、专名和用户明确提出的词。未找到释义时显示“低频词或专有名称”。

## 4. 语义近邻方案

当前不再把“词向量余弦相似度”直接当作最终结果，而是使用 **GloVe 2024 WikiGigaword 100d + ECDICT + WordNet** 的混合重排。

生成过程：

1. 从官方压缩包流式读取 100 维词向量。
2. 只保存候选词所需的向量。
3. 对所有向量做 L2 归一化。
4. 分块计算矩阵乘法，得到精确余弦相似度。
5. 对前 500 个向量候选使用 ECDICT 英文释义向量、词性和条件式高频词降权进行重排。
6. 使用 WordNet 最常用的前 4 个词义补充同义、反义、派生及两层上下位关系；词典关系候选即使不在 GloVe Top 500 中也会参与重排。
7. 同类功能词获得奖励，例如 `which → what`；功能词只在实义词查询中条件式降权，不使用全局黑名单。
8. 根据 ECDICT `exchange` 字段折叠同一词元的屈折变化，并排除普通复数。
9. 为每个词保存重排后的 40 个近邻及可选关系类型。

页面显示的是混合“关联度”，不是概率或纯余弦相似度。WordNet 按词义组织关系，而页面按单词聚合，因此多义词的标签仍可能来自非当前语境的其他词义；标签表示词典中存在该关系，不等于两个单词在所有语境中都具有该关系。

### 4.1 当前关联度公式

生成器首先取每个词的 GloVe Top 500，再将 WordNet 中有显式词典关系、但不在 Top 500 中的词追加为候选。每个候选的分数为：

```text
关联度 =
0.88 × GloVe 余弦相似度
+ 0.025                    同词性奖励
+ 0.10                     同类功能词奖励
+ 0.07 × 释义向量相似度
+ WordNet 关系奖励
- 0.065                    实义词到功能词的条件惩罚
- 最多 0.02                 候选功能词的高频惩罚
```

最后将分数限制在 `0～0.999`，排序后取前 40。这个数值只适合在当前系统内排序，不能解读为“百分之多少同义”。

### 4.2 ECDICT 重排信号

- 词性：从 ECDICT 英文释义开头的 `n.`、`v.`、`a.`、`pron.` 等标记中提取，一个词可以有多个词性。
- 释义向量：对 ECDICT 英文释义分词，去掉弱语义词，再对剩余词的 GloVe 向量取平均。
- 词形归一：使用 `exchange` 字段将 `learned`、`learning`、`learns` 等折叠到 `learn`，不占用主要近邻名额。
- 词频：使用英语词频表中的排名估计频率；仅在实义词查询周围对高频功能词降权。

功能词被分为疑问词、代词、情态动词、限定词、连接词/介词和话语副词等小组。不得将这些词作为全局停用词删除，否则会破坏 `which → what`、`can → could` 等有效关系。

### 4.3 WordNet 关系及奖励

| 数据代码 | 页面标签 | 含义 | 奖励 |
| --- | --- | --- | ---: |
| `syn` | 同义 | 处于同一 WordNet synset | `+0.14` |
| `ant` | 反义 | WordNet lemma 显式反义关系 | `+0.11` |
| `hyper` | 上位 | 直接上位概念 | `+0.09` |
| `hypo` | 下位 | 直接下位概念 | `+0.09` |
| `hyper2` | 上位 | 间隔一层的上位概念 | `+0.05` |
| `hypo2` | 下位 | 间隔一层的下位概念 | `+0.05` |
| `deriv` | 派生 | WordNet 派生词形关系 | `+0.06` |

上位词表示“该词属于什么更大的类别”，例如 `apple → fruit`。下位词表示“该类别下有哪些更具体的成员”，例如 `doctor → surgeon`。反义词不是语义相似，但对学习者关联很强，因此参与加分并显式标记“反义”。

为降低罕见词义造成的噪声，每个单词只使用 WordNet 排在前面的 4 个词义。如果同一词对同时存在多种关系，优先级是：同义 > 反义 > 直接上下位 > 两层上下位 > 派生。

### 4.4 近邻数据格式

无显式词典关系的边保持紧凑格式：

```json
[targetWordId, associationScore]
```

有 WordNet 关系的边增加第三个字段：

```json
[targetWordId, associationScore, "syn"]
```

`app.js` 根据第三个字段显示关系标签。后续修改数据格式时必须保持对两元数组的兼容。

早期版本使用字符 n-gram 哈希向量，导致 `memorable` 匹配 `cable` 等拼写相近但语义无关的词，该方案已经废弃，不应恢复。

## 5. 普通复数过滤

近邻中通常不展示单纯的复数变形。例如 `computer` 不需要显示 `computers`。

`is_regular_plural()` 根据 `-s`、`-es`、`-ies` 还原词干。如果还原后的单数存在于词库中，则从近邻候选中排除。

有独立含义的复数词通过 `PLURAL_EXCEPTIONS` 保留，例如：

- `glasses`
- `customs`
- `goods`
- `savings`
- `premises`
- `works`

添加例外时应确认该复数确实有独立词义，不要为了提高近邻数量而恢复全部复数。

## 6. 页面交互

### 搜索

- 输入时从 50,000 词中做前缀匹配并显示最多 7 个建议。
- 回车进入当前高亮建议或第一个前缀匹配词。
- URL hash 保存当前中心词，可直接分享 `#word`。

### 关系图

- 桌面端显示 36 个节点。
- 中等宽度显示 28 个。
- 手机显示 18 个。
- 数据中仍保存 40 个近邻，“刷新”按钮会轮换显示。
- 查询尚未加载的字母时，`ensureNeighborChunk()` 会优先加载对应分片；重复查询复用同一个 Promise，不重复请求。
- 前台查询未加载的字母分片时，关系图中心必须显示独立的字节进度条、百分比和已读/总大小；即使该分片已在后台下载，新的前台监听器也应立即收到当前进度。
- 首屏可用后，其他分片按浏览器空闲时间依次加载；顶栏显示后台数据进度，全部完成后显示 `offline`。
- 节点分为三圈；中心两圈间距经过调整，以减少卡片遮挡。
- 调整字号、卡片尺寸或节点数量后，必须同时检查三圈半径和图表高度，避免只改 CSS 导致重叠。

### 发音

发音使用浏览器原生 Web Speech API，不调用远程音频服务：

- 优先选择 `en-US` 语音，其次选择其他英文语音。
- 播放前取消上一条发音。
- 扬声器按钮会阻止事件冒泡，不应触发中心词切换。
- 不同操作系统和浏览器的声音可能不同，这是本地语音合成的正常差异。

## 7. 视觉设计考虑

- 页面采用清爽、轻科技感的浅色网格背景。
- 英文词使用最大、最粗、对比最强的文字。
- 中文释义较小；关联度和词典关系使用弱化的胶囊标签。
- 节点颜色按近邻排名分为四档：红、橙、青绿、蓝紫。
- 越接近中心的节点颜色和连线越醒目。
- 顶部将品牌、主标语和“50,000 words · offline”合并到一行，以节省纵向空间。
- 不要重新加入“点击周边单词继续探索”等冗余提示。

如果增加节点数量或字号，优先保证不重叠和可点击性，而不是追求单屏塞入最多信息。

## 8. 已知限制

- GloVe 是静态单词向量，不能区分同一个词在不同语境中的多种含义。
- WordNet 也是按词义而不是当前语境建模；页面未让用户先选词义，因此多义词可能混入另一个词义的关系。
- WordNet 关系不是完全对称的页面排名：一个大类可以有很多下位词，只有排名最高的部分能进入 Top 40。
- 高频词的近邻有时偏向上下文共现，而不是严格同义词。
- 人名、地名和低频词的中文释义质量不稳定。
- 26 个分片后台全部加载后仍会使用约 28 MB 原始数据和相应内存；拆分主要改善首屏等待，不减少完整会话的总数据量。
- HTTP/HTTPS 环境按 `manifest.js` 中的原始字节数显示真实进度；`file://` 本地打开时受浏览器限制，显示动态读取状态。
- CDN 的 `Content-Length` 可能是 gzip/Brotli 压缩体积，而 `fetch()` 流统计的是解压后字节，因此不能用响应头作为进度总量。
- 浏览器语音依赖用户设备中安装的语音。

如果未来某个字母分片继续变大，可在不改变外部接口的前提下改成双字母或固定索引区间分片。

## 9. 数据生成

生成器当前使用以下本地输入：

```text
/tmp/en_full.txt
/tmp/ecdict.csv
/tmp/glove.2024.wikigiga.100d.zip
/tmp/wordorbit-nltk-private/corpora/wordnet.zip
```

运行环境需要 Python、NumPy、NLTK 和 WordNet 语料。`WORDNET_DATA` 可以指向自定义 NLTK 数据目录：

```bash
WORDNET_DATA=/tmp/wordorbit-nltk-private python3 vocabulary-graph/generate_data.py
```

生成后至少检查：

- `words`、`meanings`、`neighbors` 都是 50,000 条。
- 每个 `neighbors` 都是 40 条。
- `manifest.js`、`core.js` 和 26 个近邻分片均成功生成，且没有单文件超过 25 MB。
- `runaround`、`stopover`、`layover` 等已知边界词存在。
- `memorable` 的近邻以 `unforgettable` 等语义相关词为主。
- `computer` 的近邻不包含普通复数 `computers`。
- `hot → cold` 应标记“反义”。
- `doctor → physician` 应标记“同义”，`doctor → surgeon` 应标记“下位”。
- `apple → fruit` 应标记“上位”。
- `which` 的近邻仍应包含 `what`，不得因高频功能词降权而丢失。
- `learn` 的前 40 中不应再出现 `learned`、`learning`，`what`、`can` 等弱相关词应明显下降。
- `app.js` 通过 `node --check`。

## 10. 发布与缓存

线上地址：`https://ivanalgo.github.io/vocabulary-graph/`

仓库：`ivanalgo/ivanalgo.github.io`，发布分支为 `master`。站点位于仓库的 `vocabulary-graph/` 子目录，根目录 `index.html` 有入口卡片。

GitHub Pages 有几十秒的部署延迟。推送后应确认线上文件的修改时间或内容已经更新，不能只根据 `git push` 成功判断发布完成。

修改 CSS、JavaScript 或数据后，应同步更新 `DATA_VERSION`、`manifest.js` 版本和 `index.html` 中资源查询参数，例如从 `?v=10` 改为 `?v=11`，避免浏览器和 CDN 继续使用旧缓存。

## 11. 后续修改的最低回归检查

每次明显修改至少确认：

1. 搜索和键盘上下选择正常。
2. 点击近邻可以切换中心词。
3. 返回和刷新近邻按钮正常。
4. 发音按钮只播放，不跳转。
5. 桌面和手机节点没有大面积重叠或被裁切。
6. 中文释义没有压过英文单词的视觉层级。
7. 线上 GitHub Pages 已加载新版本资源。
8. 同义、反义、上位、下位和派生标签与数据第三字段一致。
9. 抽查多义词的 WordNet 关系，不能只看分数，必须核对关系标签是否来自合理词义。
10. 在网络较慢时查询尚未加载的字母，局部进度条应从当前值持续增长，完成后正常显示节点。
