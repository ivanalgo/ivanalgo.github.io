HOW WORD ORBIT WORKS

四种关系，
四种看法。

“相关”不是一种关系。我们把语境联想、概念层级、词典关系和音形混淆分开呈现。

为什么分开四种视角关联度数据加载
01 · START WITH A QUESTION

先弄清楚，我们想找的是哪一种“相关”

查询一个单词时，出现在它周围的词可能意义相近，也可能只是经常出现在同一个场景里。

例如 doctor 与 physician 接近，是因为二者意义相近；doctor 与 hospital 接近，则更多来自共同语境。hot 与 cold 意义相反，却经常出现在相似句子里。right 与 write 发音相同，语义却完全不同。

如果把这些关系全部塞进一张图，学习者看到的只会是一个含义模糊的“相关词”列表。因此 Word Orbit 把它们拆成四种视角，让每一种关系回答一个清楚的问题。

02 · FOUR VIEWS

从自由联想，到逐层认识一个概念

01

关联星图

它回答：“谈到这个词，还容易想到什么？”星图从真实语境出发，适合寻找同一主题、场景或经常共同出现的词。例如从 doctor 可以走向 physician、hospital、patient。这里的关系是联想，不等于严格同义。

02

概念树

它回答：“这个词属于什么，它下面还有什么？”概念树按照具体词义逐层展开上位和下位概念。例如 red → color，而 color 又可以向下展开 red、blue、yellow、gray。选择其中一个词继续向下，就像在知识树中逐层行走。

03

近义词与反义词

它回答：“这个词义还能怎么表达？”系统会先让用户选择具体词义，再分别展示严格同义、近义、反义和派生关系，避免把多义词的不同含义混成一组。

04

易混词

它回答：“哪些词看起来或听起来容易弄错？”这里会区分形近、同音、近音和常见误用，例如 right、write、rite。它们的接近程度不是语义相似度，也不会混进关联星图。

03 · ASSOCIATION SCORE

词向量给出距离，词典关系帮助校准

Word embedding 技术可以把每个单词表示成一组数字。两个词越经常出现在相似语境中，它们在向量空间里的距离通常就越近。

关联星图使用 GloVe 词向量，先为每个词找到一批语境近邻。但“出现在相似语境”不一定等于“意义相近”，所以系统还会结合 ECDICT 的词性与英文释义，以及 WordNet 中明确记录的同义、反义、上下位和派生关系重新排序，并降低普通复数、屈折变化和弱语义高频词造成的噪声。

最终关联度0.88 × 语境相似度＋ 释义与词性＋ 词典关系奖励− 弱语义噪声

页面显示的“关联度”只是当前系统内部的排序分，不是概率。0.80 并不表示“80% 同义”。反义词也可能在向量空间中很接近，因为相反概念经常出现在相似的句子里；对学习者而言，明确标出关系类型比单看一个分数更重要。

具体使用了哪些开放词典和语言数据库，可以在关于本站的数据来源中查看。

04 · STATIC PIPELINE

没有远程数据库，也能逐步探索

重量级计算都在网站发布之前完成。浏览器所做的事情，是在需要时取出已经计算好的结果。

处理后的 50,000 个单词被拆成基础词库、26 个星图分片和 26 个详情分片。打开网站时先加载轻量的基础词库；查询某个单词或切换学习模式时，再加载对应字母的数据。进度条按照真实下载字节增长，让较慢的网络也有明确反馈。

  1. 离线汇集读取词频、词典、词向量和发音数据
  2. 清洗重排按词义对齐、过滤噪声、计算关系
  3. 分片发布把星图和详情数据按首字母拆分
  4. 按需加载用户走到哪里，浏览器就加载到哪里

因此 Word Orbit 仍然只是普通的 HTML、CSS 和 JavaScript，不依赖在线数据库，也不需要服务器实时运行词向量模型。
